# 通读须知（预置模板，并行档全部章节过审之后用）

这本书的各章是多位写手**同时**写的，彼此看不见；每章已经各自过了独立评审，单章内部的准确性和文风不用你管。你只管**跨章问题**。派活消息里给了你：**工作目录**（下文 `<工作目录>`）、**skill 目录**（下文 `<skill 目录>`），以及各章评审留给通读的提醒（如果有）。

## 先读

- `<工作目录>/book.json` —— 章节契约：每章 `terms` 是该章负责首次解释的名词，`owns` 是该章独占的类比 / 案例。
- `<工作目录>/seed.txt` —— 事实真源 + 边界。
- `<工作目录>/intro.html`（有的话）和 `<工作目录>/chapters/` 下全部章节，**按顺序全部读完**。
- `<工作目录>/reviews/` 下各章 JSON 里的 `for_readthrough`。

## 找并修这五类

1. **同一个名词解释了两遍** → 留 `terms` 归属的那一章，其余改成一句带过（科普书去掉多余的 `<dfn>`）。
2. **同一个类比 / 例子 / 反事实在两章重复** → 留 `owns` 归属的那一章，另一章改成一句回指。
3. **前后数字、口径、说法矛盾** → 以 `seed.txt` 为准统一。
4. **章首没接上一章留的疑问，或把上一章的场景又重讲一遍** → 压成一句承接。
5. **违反 `seed.txt` 边界** → 改掉。特别留意能被读者**反推**出禁止信息的写法（比如给了比例又给了金额，等于给了总数）；以及某一章漏了全书都有的声明。

## 规矩

- 最小改动，用 Edit。不重写章节，不动单章内部写得好不好。
- 每改完一章就重新发布它，前台跑、确认输出都是 `ok`：

  ```bash
  node <skill 目录>/wjs-voicedrop-writing-book/build.mjs done <工作目录> NN
  ```

  导读改了：`node <skill 目录>/wjs-voicedrop-writing-book/build.mjs intro <工作目录>`
- 小说另查 `bible.json`：伏笔埋了有没有回收、人名称呼时间线前后是否一致。

## 产出

把改动清单存到 `<工作目录>/reviews/readthrough.md`，并在回复里给出同一份：每条写「第几章 / 属于上面哪一类 / 改了什么」；再列出你检查过但判断不用改的重复。没有要改的就明说「通读无改动」。
