# wjs-voicedrop-writing-book — 一颗种子长成一本书（总调度）

**输入**：一个词 / 一句话 / 一篇文章（任意一种）。
**产出**：一本多章的书，发布到 R2 的 `books/<slug>/` 文件夹，经 **`jianshuo.dev/voicedrop/books/<slug>/`** 公共路由外网免 token 直达，界面淡雅，随写随发。公开入口是 `build.mjs` 跑完打印的那个 `.../voicedrop/books/<slug>/index.html` 链接。最后再走一遍：给全书配一张带书名的封面文件 `cover.jpg`（只是个文件、不嵌正文，供 voicedrop 客户端取用）。

**本 skill 管什么、不管什么**——

- **本 skill（骨架 + 流水线，所有书通用）**：工作目录与 `book.json` 结构、认证、`build.mjs` 渲染/发布、封面、断点续跑、修书模式、编排、发布路由、淡雅界面的两条硬约束、红线。
- **写作 skill（怎么写，按类型分派）**：读者画像、文风铁律、大纲怎么切、写手提示词、评审维度、该类型专属的 HTML 约定与红线。**第 1 步就得选定类型、读进对应写作 skill，后面的建筑师/写手/评审提示词全部从它来。**

先例：`/a/jingangjing/`（金刚经·理工男读本）就是这条流水线跑出来的样子——照它的骨架来。

## 第 0 步：选书的类型（分派）

先看种子/主题，判断这本书是哪一类，然后**读进对应写作 skill 的 SKILL.md**，把它的读者画像、文风、大纲要求、写手/评审提示词作为下面所有角色的依据：

| 类型 | 写作 skill | 什么时候选它 |
|---|---|---|
| **科普书 / 讲清一件事** | `wjs-voicedrop-writing-explainary-book` | 想弄懂「它到底怎么运作」——科学/技术/历史/商业/制度的因果与规律。**默认类型**：拿不准、或明显是「讲道理/讲原理」的主题，就选它。 |
| **绘本 / 图画故事** | `wjs-voicedrop-writing-chidrens-book` | 给孩子（或大人）的图画书：图为主、字极简、一个温柔的故事或概念启蒙。 |
| **小说 / 虚构叙事** | `wjs-voicedrop-writing-novel` | 有人物、有情节、有冲突的虚构故事；靠叙事而非说理推进。 |

```bash
# 举例：确定是科普书后，先把该类型的写法读进来
cat ~/.claude/skills/wjs-voicedrop-writing-explainary-book/SKILL.md
```

- **调用方若已在任务里指定了类型**（如 lab 的 /api/book 传了 `type`/`kind`），按它来，别自作主张改类型。
- **没指定就自己判断**；实在拿不准偏向科普书。判断完在 `book.json` 写上 `"type"` 字段（`explainary` / `childrens` / `novel`），`build.mjs` 会据此调整页脚/默认副标注等通用文案。
- 选定后**通篇只用这一种写法**——不要在一本书里混搭三种风格。
- **类目（`category`）也在这一步定**，八选一：`商业` / `投资` / `AI` / `科学` / `人文` / `身心` / `生活` / `故事`。`childrens` 和 `novel` 一律「故事」；科普书按主题：投资偏市场、金钱、估值；商业偏经营、产业、公司史、产品；AI 偏人工智能与软件；科学偏数理、自然、工程科普；人文偏历史、艺术、哲学、制度；身心偏健康、修行、心态、习惯；生活偏吃喝、旅行、玩乐、家事。只能用这八个词，不要自造；不写的书只出现在书架「全部」里，不挂标签。

## 四个角色（框架通用，提示词来自写作 skill）

| 角色 | 干什么 | 谁来当 |
|---|---|---|
| **建筑师 architect** | 把种子拆成一本书的大纲：书名、slug、切入角度、章节清单（每章一句 brief）、配色 | 1 个 agent |
| **写手 writer** | 每章一个，写正文 HTML 片段 | 并行档：N 个子代理并发；串行档：你自己逐章写 |
| **评审 reviewer** | 独立按该类型的维度判过不过，给反馈 | 并行档：每章 1 个子代理，**不能是该章的写手**；串行档：你自己抛开写作思路重读 |
| **发布 publisher** | 把过审章节组装成淡雅页面，增量发到 R2（经 `/voicedrop/books/` 公开） | 跑 `build.mjs done NN`——并行档由评审子代理过审当下自己跑，串行档由你跑 |

**用哪一档由任务提示词末尾的「【编排：并行档】/【编排：串行档】」决定**（服务端按引擎给：有子代理工具的给并行档）。提示词没说，就看你自己有没有 Agent 子代理工具：有 → 并行档，没有 → 串行档。两档的节拍见下面「编排」一节。

**框架是通用的，提示词是分类型的**：建筑师怎么切大纲、写手守什么文风、评审看哪几个维度——全部从第 0 步读进来的写作 skill 取。这里只规定机制：

- 评审必须**独立**：只看「章节成品 + 全书大纲（并行档再加相邻的前一章）」，**不带写手的思路**，从零判断；存疑处自己查（web）。并行档单独派子代理，写手与评审**绝不共享上下文**。
- 写→评→（不过则照 `must_fix` 重写，并行档**换新写手**）→复审，**最多 3 轮**；3 轮仍不过就降级该章（缩小野心）或记录短板后放行，别死循环。局部硬伤（一个数字、一句话）评审当场改掉即可，不必走重写。

## 工作目录约定

在**当前目录**（agent 的 cwd，即 `/opt/claude-agent/workspace/`）下的 `book-<slug>/` 攒稿——
**不要用 /tmp**（服务开了 PrivateTmp，重启就没了；workspace 是耐久盘，修书模式还要回来用）：

```
book.json            # 全书清单（见下），随进度更新
intro.html           # 导读正文 HTML 片段（可选）
chapters/01.html     # 第 1 章正文 HTML 片段（<article> 里面的内容）
chapters/02.html
...
reviews/01.json      # 第 1 章的评审意见（留痕，便于重写）
```

### book.json 结构

```json
{
  "jobId": "（调用任务里给的 jobId，原样抄进来——服务端登记簿靠它对号，漏了这本书就没有主人）",
  "owner": "（调用任务里给的 owner scope，原样抄进来——产权真源，谁能在线修改这本书以此为准；服务端也会兜底补）",
  "type": "explainary",                    // explainary | childrens | novel，决定通用文案（页脚/默认副标注）；缺省当 explainary
  "category": "科学",                       // 书架类目，八选一：商业 / 投资 / AI / 科学 / 人文 / 身心 / 生活 / 故事（见上面「类目」一条）
  "slug": "entropy",                       // 决定 books/<slug>/ 文件夹与 /voicedrop/books/<slug>/ 路径；小写、连字符、别撞已有的
  "title": "熵：为什么一切都在变乱",
  "subtitle": "从洗牌到宇宙热寂，一个工程师能摸到的无序",
  "author": "（调用任务里给的署名）",        // 只用调用方传进来的作者名；没给就整个不写这个字段，不要默认署「王建硕」
  "meta": "面向理工背景的好奇者",           // 目录页副标注，可选（缺省按 type 给中性文案）
  "tagline": "费曼式写法 · 由多个 AI 代理撰写与互相审校",  // 页脚小字，可选（缺省按 type 给中性文案）
  "tint": "#e9eef0",                       // 强调浅底色，随主题气质调
  "dark": "#2f6d7a",                       // 强调深色（标题/序号/重点），随气质调
  "introTeaser": "先别背公式，先想想一副新牌。",  // 目录页导读钩子，可选
  "chapters": [
    {"no": 1, "title": "第一章 · 一副新牌", "brief": "用洗牌讲清什么叫无序", "status": "done"},
    {"no": 2, "title": "第二章 · 时间的箭头", "brief": "为什么鸡蛋不会自己拼回去", "status": "writing"},
    {"no": 3, "title": "第三章 · 麦克斯韦的小妖", "brief": "信息就是能量", "status": "planned"}
  ]
}
```

`status`：`planned`（待写）/ `writing`（在写）/ `done`（过审已发）。目录页据此显示，只有 `done` 的章节可点开。

**章节契约（并行档必写，串行档建议写）**：并行写手互相看不见，章与章不撞车、能接上，全靠大纲把边界划死。建筑师在每个章节项里除 `no/title/brief` 外再写四个字段，顶层再加两个：

```json
{
  "thread": "贯穿全书、读完能回答的那个问题",
  "running": "贯穿全书的例子（如：一家四个股东的奶茶店）——各章都可以回到它，但不要各自另起一个同类例子",
  "chapters": [
    {"no": 3, "title": "…", "brief": "…", "status": "planned",
     "from": "承接上一章留下的哪个疑问（第 1 章写读者带着什么疑问进来）",
     "to": "本章结尾留给下一章的疑问（最后一章写读者带走什么）",
     "owns": "本章独占的类比 / 案例 / 数据——别的章不许再用",
     "terms": ["本章负责首次解释的名词", "…"]}
  ]
}
```

每个名词只归一章首次解释（`terms`），别的章用到时一句带过、不重新定义；每个类比只归一章（`owns`）。这些字段 `build.mjs` 不渲染，只给写手和评审看。
顶层还可写 `"hidden": true`——书不上书架（index 的 HTML/JSON 都不出），但文件照发、直链可看。**绘本（`type: "childrens"`）创建时缺省必须带 `"hidden": true`**（服务端也会兜底补），主人验收后修书去掉即上架；其他类型缺省不写。
`title`/`subtitle`/`meta`/`tagline`/`tint`/`dark`/`introTeaser` 的**气质与措辞由所选写作 skill 决定**——科普书是费曼式、绘本是童趣、小说是文学感；`build.mjs` 只在你没写这些字段时按 `type` 兜一个中性缺省。

## 流水线（按顺序，但**边写边发**）

> 下面每一步里，「建筑师怎么切大纲」「写手守什么文风、用哪些标签」「评审看哪几个维度」都以第 0 步读进来的写作 skill 为准；这里只讲通用节拍与命令。

### 1. 建筑师写大纲（你自己）

按写作 skill 的大纲要求（你自己当建筑师，不必为它单派子代理），产出：书名、slug、subtitle、切入角度、章节清单（每章 `no / title / 一句 brief`）、tint/dark 配色、一句 introTeaser。把结果落成 `book.json`（全部章节先标 `planned`；写上 `type` 和 `category`）。

### 2. 先发一个骨架（第一次「有进展就发」）

```bash
node ~/.claude/skills/wjs-voicedrop-writing-book/build.mjs index book-<slug>
```

目录页此刻就上线了（章节显示「待写」）。**之后每完成一点都重发一次。**

### 3. 每章：写 → 评 →（不过则重写）→ 发

对每一章跑这个循环（下面 3a–3d 是每章要过的关；**谁来跑、几章同时跑，按「编排」一节的并行档 / 串行档**）。

- **3a. 写手**：提示词按写作 skill 给（读者画像 + 文风铁律 + 该类型的 HTML 约定 + 长度）。产出**一段 `<article>` 里面的 HTML 片段**，存到 `chapters/NN.html`。通用硬约束（所有类型都守）：不写 `<h1>`（标题由模板出）；不写内联 `style`；不编造图片 URL；内链一律相对文件名。
- **3b. 评审（独立！）**：只看「该章成品 HTML + 全书大纲」，按写作 skill 的评审维度打分并给 `must_fix`，输出 JSON 存 `reviews/NN.json`（约定字段：`{"scores":{...},"verdict":"pass|fail","must_fix":["…"],"note":"一句总评"}`）。
- **3c. 不过就重写**：把 `must_fix` 交给一个**新的**写手（并行档另派子代理，别复用原写手上下文），照单重写 `chapters/NN.html`，再回 3b 复审。最多 3 轮。
- **3d. 过了就发**（**落盘即发，绝不攒到最后**）：
  ```bash
  # 先把过审正文写到 chapters/NN.html（落盘=durable 检查点），然后一步到位：
  node ~/.claude/skills/wjs-voicedrop-writing-book/build.mjs done book-<slug> NN   # 标 done + 落 book.json + 发该章 + 刷新目录
  ```
  `done` 把「改状态 / 发该章 / 刷目录」合成一次原子操作。读者立刻能读到新章，目录 `x/N` 前进。

> **为什么必须每章即发**：正文一旦落到 `chapters/NN.html` 且 `build.mjs done` 过，这一章就**永久在盘上、且已上线**——哪怕会话被切断，都不影响已发的章。这是长书的抗断点设计。**绝不**把整本攒到最后一次性发。

### 3.5 断点续跑（长书必看）

磁盘就是检查点。任何时候被打断，回来先跑一句看还差哪些：

```bash
node ~/.claude/skills/wjs-voicedrop-writing-book/build.mjs status book-<slug>   # 列出每章 done / 待发(有稿) / 待写
```

- `✓ done`：已上线，别重写别重发。
- `· 待发(有稿)`：正文已落盘但没发 → 直接 `build.mjs done <NN>`。
- `待写`：才需要重新走 写→评→发。

**据此只补没做的章，绝不从头重来。**

> **恢复演练（被切断后先做这三步，别急着重写）**：
> 1. **R2 才是「已发布」的最终真相**——`status` 只读本地 `book.json`，两者可能错位。先直接探 R2：
>    `for n in $(seq -w 1 16); do echo -n "$n "; curl -s -o /dev/null -w '%{http_code}\n' https://jianshuo.dev/voicedrop/books/<slug>/$n.html; done`（200=已发、404=没发）。
> 2. **对账**：R2 有的 = 真 done，别重发；本地有稿但 R2 404 = 直接 `build.mjs done NN` 补发（先抽读一章确认质量再批量发）；本地无稿且 R2 404 = 才真要重新走 写→评→发。
> 3. **本地全空但 R2 有章** = 环境被重置：用「修书模式」的 `build.mjs pull` 从线上源稿镜像拉回，再只补 404 的章。

### 4. 导读页（可选，建议有）

全书过半后，按写作 skill 的导读要求写 `intro.html`（也走写→评），发：
```bash
node ~/.claude/skills/wjs-voicedrop-writing-book/build.mjs intro book-<slug>
```
并在 `book.json` 里填 `introTeaser`，重发 index。

### 5. 收尾

全部 `done` 后再发一次 index（`build.mjs index` 或 `all`）。把它打印出来的公开链接
`https://jianshuo.dev/voicedrop/books/<slug>/index.html` 给用户——外网可直接打开。

## 修书模式（书写完后，主人在 App 里持续修改）

调用方（lab /api/book/revise）会给你 **slug** 和主人的**修改指令**。铁律：**文件是真源，不是记忆**——一切以工作目录 + 线上成书为准。

1. **重建/复用工作目录**：`ls book-<slug>/book.json` 在就直接用；不在就
   `node ~/.claude/skills/wjs-voicedrop-writing-book/build.mjs pull book-<slug> <slug>`
   从线上 `_src` 源稿镜像拉回（book.json + 各章片段 + 导读 + 封面）。
   pull 报「没有 _src」= 源稿镜像上线前的老书：手工重建——抓渲染页各页 `<article>…</article>` 里的正文片段存 `chapters/NN.html`，按目录页信息手写 book.json（全部标 done），再继续。
2. **先读 book.json 认出类型**（`type` 字段），把对应写作 skill 读进来，再动手；改内容要守该类型的文风与评审。只改与指令相关的文件，无关章节**一个字都不动**。
3. **大改保持水准**：新增/重写整章仍走「写→独立评审→不过重写」；小改（错别字/换说法）直接改。淡雅界面两条硬约束照旧。
4. **改完即发**：动过的章逐章 `build.mjs done book-<slug> NN`；只动 book.json/导读就 `index`/`intro`；换封面就 `build.mjs asset book-<slug> cover.jpg cover.jpg`。
5. **收尾输出「修改说明」**：最后一条消息只输出一段 200 字以内、给书的主人看的说明——改了什么、动了哪几章、为什么。会原样进 App 的修改记录，别写寒暄/内部术语。

## 发布机制：/voicedrop/books/ 公共路由（要点，别抄错）

`build.mjs` 把整本书发到 **R2 的 `books/<slug>/` 文件夹**（写走 files API：`PUT /files/api/upload/books/<slug>/<file>`，`Content-Type: text/html`），经 **`jianshuo.dev/voicedrop/books/<slug>/`** 这个专门的公开只读路由外网直达。

- **页面结构**：`books/<slug>/index.html`（封面+目录）、`intro.html`（导读）、`01.html…NN.html`（每章一页）。用真 `.html` 文件、真 `text/html` 类型。
- **路由特性**：免 token、**`no-store` 不缓存**，所以**重发即刷新**，不需要 `?v=` 破缓存。该路由只读（直接 PUT/POST 会 405）。
- **内链**用相对文件名 `NN.html`；`build.mjs` 打印的公开入口是完整 URL。
- ⚠️ **读写要对上同一个 store**：写入落在**本账号 scope** 的 `books/<slug>/`。若发完访问 `/voicedrop/books/<slug>/index.html` 是 404，多半是该路由指向了别的 store——这是后端配置，把本账号 scope（`GET /files/api/whoami`）告诉后端去对齐即可。

## 淡雅界面（已内建在 build.mjs，所有类型通用）

暖米纸底（`#f7f2e7`）+ 宋体正文 + 单一强调色（随书 `tint/dark` 走）+ 720px 阅读栏 + 大行距。目录页是章节清单带进度徽标；章节页有上/下章导航和回目录。要换气质**只调 `book.json` 的 `tint/dark`**，别在正文片段里写内联样式。改版式才动 `build.mjs` 里的 `CSS`。

**两条不可回退的硬约束**（改 `build.mjs` 时务必守住）：

1. **内链一律相对**：内链只写文件名 `href="01.html"`、`href="index.html"`；回书架用 `href="../"`。**绝不写** `/voicedrop/books/<slug>/…` 根绝对路径——它在 voicedrop.cn（EO 剥前缀）上每次点击会多一次 301。`build.mjs` 里 `linkPath()` 已返回纯文件名，别改回带前缀。
2. **零外部资源**：页面**不引任何外部 CSS/JS/字体/CDN**（尤其 **Google Fonts**）——国内读者会超时白屏。字体只靠 CSS 里的系统字体栈兜底。`build.mjs` 的 `head()` 里已无字体外链，保持这样。

> 说明：CSS 里带了通用件（如 `.plain` 大白话盒子、`dfn` 虚下划线），是**按需使用**的——某类型（如科普书）用得上就用，用不上（如小说）不写这些标签即可，不影响其它类型。

## 第 6 步：封面 + 必要时插图（都在正文之后）

**所有图片一律用 `/opt/claude-agent/bin/paint` 生成——动手前先完整读 `paint` skill（`~/.claude/skills/paint/SKILL.md`，出图说明书：清单、选项、退出码、错误码）**，timeout 设 600000ms。**绝不用任何本地生图/改图/叠字工具**（ImageMagick、PIL、canvas、自绘字…全禁）——包括封面上的文字，也让出图模型直接画进图里。图片用 `build.mjs asset` 上传，内链一律相对，遵守两条硬约束。

**整本书一个画风（硬规则）**：paint 背后有两个引擎（Codex gpt-image-2 / 火山方舟 Seedream），画风明显不同。这本书的**每一张图**（封面、refs.png、每页插图）都带 `--group <slug>`：engine-router 给这个 group 定一个引擎后，这本书之后的所有批次都用它，中途不换——所以不用对账，也别自己 `--engine` 点另一个引擎重画。

> **插图密度按类型走**：科普书默认**不配**插图（除非某概念不画就讲不清）；绘本**以图为主**、几乎每页都要图；小说一般不配图或只配少量氛围图。具体规则见各写作 skill。这里只讲通用的封面。

**形象铁律：缺省只有汪汪（所有类型通用，封面、refs.png、插图都算）**：
- **主人（种子/修书指令）没点名的形象，一个都不许引入**——不自创新的动物、玩偶、吉祥物、拟人角色或有名有姓的人物形象画进图里，也不让它们在绘本故事里登场。
- **需要一个人物/角色形象、但主人没指定是谁时，一律用汪汪**（绘本固定角色库里的小狗，CRS 在 `~/.claude/skills/wjs-voicedrop-writing-chidrens-book/characters/wangwang-crs.png`，形象要点见该 skill 的角色表；出图带 CRS/refs.png 参照，照角色库用法画）。
- 主人点了名的：点名的是固定角色库里的（嘟嘟、小杰、小达、米拉、小饼干、小西、汪汪）→ 按 CRS 画；点名的是库外的新角色 → 照主人的描述画，并只画这些点了名的。
- 风景、建筑、物件、抽象背景不算「形象」，照常画；路人/人群只能是不抢戏的远景背景，不给名字、不给戏份。

### 封面 cover.jpg（每本都要，但只是个文件）

一张竖版封面，存成 `<workdir>/cover.jpg`、用 `build.mjs asset` 传成 `books/<slug>/cover.jpg`。

- **它只是放在书目录里的一个文件，供别的工具（voicedrop 客户端）取用显示——不嵌进正文页/目录页**（`build.mjs` 不会把它渲染进任何 HTML）。
- **平面封面（硬规则，2026-11-21 起）**：画的就是**封面这一面本身**，正对镜头、满版铺满整张图、四边到头。**绝不画成一本书的立体效果图**——不要书脊、书本厚度、翻页、透视角度、投影/倒影、桌面或摄影棚背景、拿在手里的书、书架上的书。「变成书的感觉」是书架和客户端负责做的（它们会给封面加书的立体效果），图里再画一本书就成了书中书。提示词里明确写「flat front cover artwork, full-bleed, edge to edge, straight-on, no 3D book mockup, no spine, no shadow, no background scene」，中文同义也写上。
- **必须有明显的书名**，有作者就写上作者；文字放在**抽象背景的空白区之上**。让出图模型直接把文字画进图：提示词里描述抽象背景（随书配色、留白充足）+ **一字不差列出**书名/副标题/作者，并写明「画面上只允许出现这些文字，不要多余字符/水印/乱码」。中文书名一般能画准，糊了就重跑或精简书名。
- **默认大标题排版**：整张封面**以文字为主角**——主标题非常大、粗、占据上部约满宽（长了分两行）；副标题约为主标题一半大小、紧跟其下；作者中等、底部居中。背景退为衬托。
- **尺寸固定用 `--size 1024x1536 --group <slug>`、输出存 `.jpg`（竖版 1:1.5）**，格式和压缩 80 按扩展名自动定。书里所有上传的图（封面、插图）一律 JPG q80，`build.mjs asset` 拒收 PNG。插图尺寸常用 `1024x1024`/`1536x1024`，别的比例服务端也会自动规整，但全书尽量统一。

**封面什么时候画**（2026-11-25 改）：书名、副标题、作者在大纲阶段就定了，技术上骨架发出去之后随时可以画，但出图耗时不可控（一分钟到五分钟以上），**绝不能让它挡在正文前面**——并行档放最后一波、和通读并行；串行档放在全部章节发完之后。绘本例外：封面要带 `refs.png` 参照，和页图同一份清单一起出。插图仍是最后一遍，别打乱正文「过审即发」的节奏。

### 多张图一起画：一份清单一次交（2026-10-28 起）

凡是一次要画两张以上（绘本的页图、带插图的书的几张插图加封面），把它们**全部写进一份清单**，一条 `/opt/claude-agent/bin/paint 清单.json --group <slug> --label 书名` 交完，别拆批、别一张一张串行地等。清单是 JSON 数组，每项 `{"out","prompt"}` 必填，`image/size/quality` 可选，与单张参数同义。engine-router 整批定一个引擎、每账号 4 张并发排队画。它是**前台命令**，约 9 分钟内必返回：退出码 0 全好；**3 = 还没画完，原样重跑同一条命令接着等**（不会重复画）；1 = 有图失败，照 paint skill 的错误码表处理后原样重跑（画好的自动跳过）。Bash timeout 给 600000ms。只画一张封面时直接 `paint "提示词" cover.jpg --group <slug>`。风格拿不准参考 `wjs-voicedrop-choosing-cover`（淡雅、浅底、别廉价海报感），封面气质也随书的类型走。

## 编排：并行档 / 串行档

2026-11-24 实测：串行写一本 10–14 章的科普书要 17–25 分钟，其中 85% 是在等模型逐章出字，每章要 4–5 个来回（写 / 评 / 发 / 一句旁白）。提速只有两条路：**让章节同时写**（并行档），和**少走来回**（串行档）。两档共同的铁律不变：**每一步都在单个回合内跑完并落成持久状态**——过审即 `build.mjs done`，没有在飞的工作跨越回合；子代理一律前台（同一条消息里并发派出、等它们全部返回），绝不丢后台。

`build.mjs` 自带工作目录锁（`.build.lock`），多个 `done` / `asset` 同时跑不会互相覆盖 `book.json`，所以并行档里评审可以各自发布。

### 并行档（有 Agent 子代理工具时；科普书默认走这档）

你是主循环：自己当建筑师，其余全部派子代理。**子代理没有你的上下文**——每次派活都把这几样写全：工作目录绝对路径、要读的文件（`book.json`、写作 skill 的 SKILL.md 绝对路径、样板章）、要写的文件绝对路径、长度、这一章的契约。

| 波次 | 同一条消息里并发派出 | 做完的标志 |
|---|---|---|
| **0 · 大纲** | 你自己：读两个 skill（并发 Read）→ 写 `book.json`（含章节契约）→ `build.mjs index` 发骨架 | 目录页上线 |
| **1 · 样板章** | 第 1 章写手（只这一个，别搭别的——它一落盘就要立刻进下一波） | `chapters/01.html` 落盘 |
| **2 · 全体写手** | 第 1 章评审 ‖ 第 2…N 章写手（各读 `chapters/01.html` 对齐语气，只写自己那章）‖ 导读写手 | 第 1 章上线；其余章节稿落盘 |
| **3 · 全体评审** | 第 2…N 章评审 ‖ 导读评审 | 过审的章各自上线 |
| **4 · 返工**（有 fail 才有） | 每个 fail 的章派一个**新**写手照 `must_fix` 重写 → 再一波评审；最多 3 轮 | 全部 done |
| **5 · 通读 + 封面** | 通读子代理 ‖ 封面子代理（读 paint skill → 画 `cover.jpg` → 看图校字 → `build.mjs asset … cover.jpg cover.jpg`） | 全书无重复 / 矛盾；封面上传 |
| **6 · 收尾** | 你自己：`build.mjs status` 对账 → `build.mjs all` → curl 抽查 | 给出公开链接 |

要点：

- **种子落盘当事实真源**：大纲阶段就把调用方给的种子全文原样存成 `book-<slug>/seed.txt`。种子里常带着事实、数字和「不许写什么」的边界（如不写账户总额、不提某个名字）——写手只许用里面的事实，评审拿它逐个核对数字，通读拿它查边界。你写章节契约时也要先对一遍种子的边界，别在 `owns` 里要求写手写出种子禁止的内容（2026-11-24 演练里契约写了「最大亏损 ÷ 5% 倒推」，写手照做就算出了种子明令不写的账户总额）。
- **须知写成文件，派活只说一句**：把写手须知、评审须知各写成一个文件放在工作目录旁（`WRITER.md` / `REVIEWER.md`：要读哪些文件的绝对路径、规矩、产出路径、发布命令原文），派子代理时只写「先读 X 并照做，你负责第 N 章」。十几个子代理的提示词一条消息就发得完，口径也一致。
- **第 1 章先写**有两个用处：最早有一章能读（配合「第一章上线」推送），以及给其余写手一个语气样板。**这一波只放它一个**：你要等同一波的子代理全部返回才能派下一波，搭上任何慢的东西，第 1 章就上不了线。
- **封面放在最后一波，和通读一起**（2026-11-25 改）：出图耗时不可控——平时一分钟，排队时四五分钟甚至更久。放在前面的波次里，整波都要等它，正文全被堵住（上线第一单《CRWV》把封面和第 1 章放同一波：第 1 章第 7 分钟写好，出图卡了 4 分多钟，下一波迟迟派不出去）。放在最后，和约 3 分钟的通读并行，再慢也只拖收尾。书架上这本书在封面出来前先用无封面样式，不影响阅读。
- **评审子代理过审即发**：评审只读「该章成品 + `book.json` 全书大纲 + 相邻的前一章成品（查衔接与重复）」，按写作 skill 的维度打分、存疑处自己联网查证，写 `reviews/NN.json`。判 `pass` 就自己跑 `build.mjs done book-<slug> NN` 并确认输出里有 `ok`；判 `fail` 不发布，把 `must_fix` 原样返回给你。
- **局部硬伤评审直接改**：错一个数字、一句话有歧义、一个名词漏了解释——评审用 Edit 当场改掉，在 review 里记 `"fixed": ["…"]`，然后判 pass 发布。要重写一段以上的才判 fail 换新写手。
- **写手与评审绝不是同一个子代理**，也不把写手的思路喂给评审。
- **通读子代理**（并行档独有，补上「写手互相看不见」这一课）：把全部章节 + 导读按顺序读一遍，只找跨章问题——同一个名词被解释了两次、同一个类比 / 例子在两章重复、前后数字或说法矛盾、某章开头没接上一章留的疑问（或把上一章的场景又重讲一遍）、违反 `seed.txt` 边界的内容。各章评审报告里「留给通读」的提醒，派通读时一并转给它。用最小的 Edit 修掉（删重复的那次解释、换掉撞车的类比、补一句承上启下），**不改单章内部写得好不好**。返回它动过的章号；它自己对每个动过的章跑 `build.mjs done NN` 重发。
- **一条消息最多派 10 个子代理**；章节更多就分两条消息。某个子代理报错 / 没写出文件，下一波补派，不要整波重来。
- 你自己不写正文、不逐章旁白；每一波一条消息，等结果，下一波。
- **小说不并行写**：连续性档案 `bible.json` 要一章接一章更新，写手按顺序跑（你自己写或一次一个写手子代理），只把评审和封面并行出去。**绘本**的文字很少，你自己一次把全部页写完再评，瓶颈在出图——照旧一份清单一次交。
- **修书模式**里新增 / 重写整章，同样可以派写手 + 独立评审子代理。

### 串行档（没有子代理工具时）

你自己分步扮演所有角色，质量规矩不变（写完一章，抛开写作时的思路按评审维度重读，意见落 `reviews/NN.json`，不过就改，最多 3 轮）。省时间靠**少走来回**——每个来回都要十几二十秒的固定开销，和这一回合写多少字关系不大：

- **一条消息里发多个工具调用**，按书写顺序执行。标准节拍是每章两个来回：
  1. `Write chapters/NN.html`（写这一章）
  2. `Write reviews/NN.json`（评这一章；有局部硬伤先 `Edit` 改掉）＋ `Bash build.mjs done book-<slug> NN`（发布）——同一条消息；评审不过、需要重写段落以上时，这一条消息里只落评审意见，下一条重写。
  
  熟练后可以再并一步：评审通过时，把「评上一章 + 发上一章 + 写下一章」放进同一条消息。
- **不发只有旁白的回合**：不要单独输出「第 N 章已上线，继续第 N+1 章」再开下一个来回。
- 开头两个 skill 的 Read 放同一条消息；发布凭据和 `build.mjs` 都在，不用先 `ls` 探查；`mkdir` 和写 `book.json`、`build.mjs index` 尽量合并。
- **封面放最后**：串行档里出图是前台命令，画的时候什么都干不了，而它一分钟到五分钟以上都有可能——所以等全部章节都发完再画，别让读者等正文的时候你在等图。

### 为什么没有 Workflow

`Workflow` 跑在后台、命寿绑在当前会话进程上，会话一切就成孤儿；服务器上的引擎也没有这个工具。**保证的从来不是「进程不被切」，而是「切了也无损」**：磁盘（`chapters/NN.html` + `book.json`）和 R2 才是检查点——断了就按 3.5「断点续跑」对账，只补没做的。

## Red Flags（通用；踩到就退回。文风类红线见各写作 skill）

- 没先选类型 / 没把对应写作 skill 读进来就开写 → 建筑师和写手会跑偏，回第 0 步。
- 一本书里混搭多种风格（一半科普一半小说腔）→ 选定一种通篇执行。
- 并行档里评审和写手是同一个子代理 / 把写手的思路喂给了评审 → 不算独立，重来。（串行档只有你一个，靠「抛开写作思路重读」。）
- 全写完才发第一次 → 违反「有进展就发」，发完骨架就上线、每章过审即发。
- 把整本攒到最后一次性发 → 会话一切全丢。必须每章过审即 `build.mjs done NN`。
- 并行档里把子代理丢后台、或一个一个串行地派 → 前者回合一结束就被杀，后者白白丢掉并行。同一波写在同一条消息里前台并发。
- 并行档的大纲没写章节契约（`from/to/owns/terms`）就派写手 → 各章会重复解释同一个名词、撞同一个类比。回建筑师补契约。
- 并行档把封面（或任何出图）和写手 / 评审放在同一波 → 出图一慢整波都卡住、正文上不了线。封面只和通读同一波。
- 并行档跳过通读 → 跨章重复和矛盾没人看得见。全部过审后必须通读一遍。
- 串行档每章四五个来回、每发一章单独旁白一句 → 整本多花十分钟。按「编排 · 串行档」合并工具调用。
- 被打断后从头重跑 → 先探 R2（curl 各章 200/404）再 `build.mjs status` 对账，只补没做的。别只信本地 `status`。
- 把 `paint` / `build.mjs` 用 `run_in_background`、`nohup`、`Monitor` 丢到后台，然后写一段「出图后我会……」的总结结束回合 → **回合结束 = 进程退出，后台任务全被杀**（2026-09-23《一封一封的写》14 页只发了 1 页，runner 还照常推送了「书写好了」）。画图/发布一律前台同步跑到出结果（多张图写进一份清单前台交，退出码 3 就原样重跑接着等，不是丢后台）；**全部章节 done + 封面上传 + index 刷新之后才许结束回合**。服务器收尾会对账 `book.json`，没齐会把你叫回来续写，续写仍不齐按失败退款。
- 死循环重写 >3 轮 → 降级该章，记录短板，放行。
- 发完 `/voicedrop/books/<slug>/index.html` 还是 404 → 不是没发成，是路由没读本账号的 `books/` 前缀（读写 store 没对上）；`PUT /files/api/upload/books/...` 返回 200 就算成功，别反复重传，去对齐后端。
- 直接对 `/voicedrop/books` 发 PUT/POST → 405，它只读；写一律走 `/files/api/upload/books/...`。
- 正文片段里写内联 `style` / `<h1>` → 破坏淡雅基调，交给模板。
- 内链出现根绝对路径 `/voicedrop/books/…` → 违反硬约束 1，改回相对文件名。
- 页面出现 Google Fonts 或任何外部 CSS/JS/字体 → 违反硬约束 2，删掉、只用系统字体栈。
- 用了本地生图/改图/叠字工具 → 违反「图片全走 paint」，重做；封面文字也让出图模型画进图。
- 出图没带 `--group <slug>`，或自己用 `--engine` 点了跟这本书不同的引擎 → 画风混着，全书统一按 group 重画。
- 把 cover.jpg 渲染进正文/目录页 → 封面只是文件、供别的工具取用，不进 HTML。
- 封面没有清晰可读的书名 → 不合格，重画。
- 封面画成了一本立体的书（看得到书脊/厚度/投影/桌面背景，像产品效果图）→ 不合格，按「平面封面」硬规则重画（2026-11-21《新 Siri 调教指南》就是这样被打回的）。
- 图里/绘本里出现了主人没点名、又不是汪汪的角色形象（自创的小兔、小猫、新吉祥物、有名有姓的新人物）→ 违反形象铁律，换成汪汪或删掉，重画。
