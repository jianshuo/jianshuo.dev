✓ 已经做对、新系统必须继承的习惯

  • 隐私红线：只送行为元数据，录音 / 转写 / 正文 / 提示词一律不进分析系统。
  • 没配 key = 整体不启用，App 与 Worker 行为零变化；埋点 best-effort，绝不 throw。
  • 中文事件名，读事件流不用查字典（「录音上传完成」「修书已受理」「追问跳过」）。
  • 成对埋发起 + 落地，失败带可归因的原因，不是一个 bool。
  • 口径显式版本化：改了度量定义就 bump 口径，查数按口径过滤，禁止混算。

事件名没有注册表

56 处字符串字面量，改名、拼错、漏带属性线上无人拦；20 个测试文件里 0 个碰埋点。

全局属性太薄

只有界面 / 当前录音，没有线路（cn/cf）、版本、内部用户标记——切不了分群，自己的数据混在正式数据里。

服务端几乎是黑的

4 个事件全在 referral / 分享页。挖矿、ASR、成文耗时、写书失败、退款全在日志里，产品侧最贵的那段无数据。

三套 distinct_id 不通

分享页用 vid、邀请用 ipHash、App 用 sub，「分享页访问 → 装 App → 首次录音」这条最值钱的增长漏斗拼不出来。

明文 IP 调试开关未翻回

2026-07-17 归因排查打开的 DEBUG_PLAINTEXT_IP 至今还开着，ipHash 现在就是明文 IP。

无采样、无配额、无自检

录屏 30 天全量，量起来成本不可控；改完埋点只能人肉刷 Activity 看有没有送到。

埋点代码写起来要比不写还省事，否则没人会好好埋。

编号功能需求验收口径

FR-02未配置即整体停用，App 行为零变化缺 key 时无网络请求、无磁盘写入、无日志噪音P0
FR-03全局上下文自动附加：版本、build、平台、系统版本、线路（cn/cf）、语言、商店区域、是否内部用户任意一条事件都能按线路 / 版本切分，不必单独埋P0
FR-04会话上下文可注册 / 注销：当前界面、当前对象 id进入界面自动记「界面进入」，离开自动清对象P0
FR-05计时器原语：start / end 自动算耗时秒上传、成文、写书这类跨异步边界的耗时不必各写一遍P1
FR-06成对事件原语：一次调用产出「发起 / 成功 / 失败」三态，失败强制带原因不允许只埋成功；失败无原因时编译期或测试期报错P1
FR-07内部用户标记（TestFlight / 开发机 / debug）自动打 internal所有看板默认排除，可一键包含P1

编号功能需求验收口径
FR-08事件注册表是唯一真源：一份声明文件列出全部事件名、属性、类型、必填性、口径版本、负责人新增事件先改注册表，再写代码P0
FR-09代码里禁止裸字符串事件名，用注册表生成的常量 / 枚举拼错 = 编译不过P0
FR-10Schema 校验：属性缺失、类型不符、未声明属性 → 本地报错、CI 拦截单测覆盖每个事件的属性契约P0
FR-11口径版本是一等公民：改了度量定义必须 bump，查询层默认按口径分组而非混算折线图上的断点能自动标注「此处口径 2→3」P0
FR-12事件生命周期：标记 deprecated、记最后出现时间，自动列出「已死事件」与「有代码没数据」每月能生成一份事件体检报告P1
FR-13注册表一键导出成人话事件字典：什么时刻打、口径是什么、别跟谁混算半年后自己看得懂P2
