Lumino 需求列表

记录的内容：

1. 录音完成、上传开始、上传完成：耗时、文件大小、录音时长
2. 挖矿开始、成功、失败
3. ASR 耗时
4. LLM 耗时和 token 数
5. 成文总耗时
6. 写书、修书：受理、完成、失败、走的是哪条腿（kimi/codex/claude）、是否降级
7. 封面生成：成功或失败、失败原因（429 额度等）
8. 追问：展示、回答、跳过
9. 退款、扣费、充值、订阅
10. 分享页访问（文章、社区、书、小程序卡片）、点下载、App 首次启动、首次录音、首篇成文
11 邀请人、渠道、落地码沉淀成用户属性

硬需求：
1. 单一埋点入口，一行调用：track(事件, 属性)，不要多处，多种
2. 未配置即整体停用，App 行为零变化
3. 全局上下文自动附加：版本、build、平台、系统版本、线路（cn/cf）、语言、商店区域、是否内部用户
4. 会话上下文可注册 / 注销：当前界面、当前对象 id
5. 计时器原语：start / end 自动算耗时秒
6. 成对事件原语：一次调用产出「发起 / 成功 / 失败」三态，失败强制带原因
7. 内部用户标记（TestFlight / 开发机 / debug）自动打 internal

记录环节：
1. 本地持久化队列 + 批量上报，进程被杀不丢事件
2. 离线 / 弱网自动重试、指数退避，上限后丢弃并计数
3. 每条事件带客户端 event_id + 时间戳，服务端幂等去重
4. 埋点失败绝不影响主路径：不阻塞、不抛错、不弹窗

身份：
1. 归因来源沉淀为用户属性（邀请人、渠道、落地码）
2. 用户属性可写可查：算力档位、是否订阅、文章数量档位、注册日
3. 一次用户旅程一个 trace_id，客户端 → Worker → 各阶段共享，可串成瀑布图

导出：
1. 事件原始数据自有可导出，不被平台锁死
2. 支持 SQL 或等价的即席查询，能按任意属性切分、分组、开窗

显示：
1. 可以显示原始的数据流
2. 按照用户获取，用户使用等维度形成报表
