问题

被测的是什么

VoiceDrop 把口述录音挖成公众号文章，靠的是一条 system prompt（MINE_SYSTEM）。它把「拆几篇、守什么硬底线、什么文风」都讲清楚了，唯独几乎没讲标题该怎么写——而标题恰好是评审的打分维度之一。

假设很直接：补一句标题指引，标题会不会变好？会不会顺带把别处搞坏？这类问题不能靠「跑一遍看两眼」拍脑袋，得让它变成一次可复现的测量。

方法

一台本地评估台

整套 harness 跑在开发机的订阅上，不花计量 API 的钱。三根支柱：

  • 金标集（golden set）：16 条冻结的真实录音转写，从 45 字到 19062 字、含 3 条多主题、覆盖九类话题与五种情绪。每个 prompt 版本都跑同一组，差异才能干净归因到 prompt 而非选样。
  • 成对双盲评审：同一段转写，冠军版与候选版各挖一次，产出 A/B 顺序随机打乱，交给一个不知道谁是谁的裁判，逐维度判「A 优 / B 优 / 相当」。只比谁好，不需要标准答案。
  • 单变量：候选 = 冠军 + 唯一一句标题指引。任何差异都只能来自这一处。

＋ 标题写法：每篇标题用一句胸有成竹的断言，点出这篇最核心的判断或结论；不用「为什么…」「如何…」这类提问式钩子，不卖关子、不堆形容词。

两轮

第一轮说「不行」，其实是噪声在说话

第一轮 16 条各跑一次。结果卡在 60%——没过 70% 晋级线，机器判 HOLD。但翻开逐条理由，问题不在标题：大量胜负是被「某一版这次恰好编造了一句」触发忠实一票否决决定的。那是单次采样的随机性，不是 prompt 的锅。于是第二轮做两件事——把一条 49 字残句（两版都正确返回空、却被误判为回退）移出金标集；每条改跑 3 次取多数票去噪。

诚实的注脚

78.6% 该怎么读

把话说满是不诚实的。这次测量有两个必须讲清的边界：

别把 78.6% 读成「候选强 28 个百分点」

逐条胜负里，相当一部分仍由「某版这次随机编造一句」的忠实否决决定——那是生成噪声。最该归因到这次改动的硬增益是「标题 22:14」和「文风 25:16」。78.6% 的正确读法是：候选至少不更差，且标题明确更好。

  • 单次采样噪声大：这正是第一轮 60% 的成因。多样本多数票是这套 harness 之后每轮的标配，而非可选项。
  • 金标集会「污染」结论：那条 49 字残句本是「无内容」用例，却被质量 proxy 误判为回退、逼出了 HOLD。已移出——质量 fixture 与边界 fixture 要分开。

下一步

机器判 PROMOTE，最后一票在人

这是一处纯追加的指引——改不坏，最坏被忽略。去噪后标题显著变好、其余不劣、总判达标。按 harness 的规矩，达标只是拿到晋级的资格；把候选写回生产版的最后一票，永远是王建硕本人。文风这件事，机器只负责便宜地筛掉明显更差的，品味不外包。
